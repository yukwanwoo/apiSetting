# 메소 라이브 룰렛

Node.js 기반 후원 메소 룰렛과 OBS 브라우저 오버레이입니다. 기본 시작 메소는 **30,000,000**, 음수 잔액은 기본 허용입니다.

## 실행

Node.js 22 이상이 필요합니다. 외부 npm 런타임 의존성은 없습니다.

```sh
cd /workspace/apiSetting
npm ci --ignore-scripts --no-audit --no-fund
npm start
```

로컬 컴퓨터에서는 `http://127.0.0.1:3000`을 열고 `data/keys.json`의 `admin` 값을 관리자 키로 입력합니다. 키는 첫 실행 시 생성되며 콘솔에는 출력하지 않습니다. `data/`에는 인증 정보와 방송 기록이 있으므로 공유하거나 Git에 커밋하지 마세요.

개발 모드: `npm run dev`. 별도 환경 변수 파일 사용: `.env.example`을 `.env`로 복사해 값을 설정하고 `node --env-file=.env src/server.js`로 실행합니다. `.env`는 자동 로드되지 않습니다.

기본 서버는 로컬 주소에만 바인딩합니다. 다른 컴퓨터의 OBS에서 사용하려면 접근 가능한 서버 주소와 `HOST`, `PORT`를 설정해야 합니다. 외부 공개 시 HTTPS 리버스 프록시와 접근 제어가 필요합니다. 클라우드에서 실행한 주소는 사용자 PC의 localhost와 같지 않습니다.

| 기능 | 상태 |

| 공격·방어 룰렛, 추가·삭제, 조건 금액 편집 | 구현 |

| 애니메이션·결과 표시 시간 설정 | 구현 |
| FIFO 후원 대기열, 영구 이벤트 ID 중복 방지 | 구현 |
| 기본 시작 잔액 설정, 초기화, 음수 잔액, 잔액 직접 설정 | 구현 |
| 투명 OBS 룰렛·잔액 오버레이, 실시간 SSE 갱신 | 구현 |
| 방송·후원 URL 저장 화면 | 구현. URL 저장만으로 플랫폼 연결되지 않음 |
| YouTube OAuth 계정 연결, Super Chat·Super Sticker 조회 | 구현. 실제 계정 연결 검증은 미실행 |
| 치지직·SOOP·투네이션 공식 계정 인증 및 자동 후원 수집 | **미구현. 플랫폼별 후원 수신 브리지 추가 필요** |
| 네 플랫폼 공통 서명된 후원 수신 API | 구현. 각 플랫폼의 원본 API/웹훅 형식과 다름 |

**네 플랫폼의 모든 후원을 자동으로 수집하는 완성품은 아닙니다.** 방송 URL에는 후원 접근 권한이 없고, 이 저장소에는 치지직·SOOP·투네이션의 원본 후원 이벤트를 읽는 어댑터가 없습니다. 테스트 후원은 실제 연동 증거가 아닙니다. 연결 화면에서도 브리지 필요·인증 필요·실제 연결됨을 구분합니다. 후원 서비스 계정·앱 권한 확보와 플랫폼별 공식 API 문서 확인이 다음 연동 작업입니다. 비공식 세션 쿠키 추출이나 플랫폼 내부 API 스크래핑은 구현하지 않았습니다.

## 룰렛 설정

- 기본 공격 조건: 1,000원. 기본 방어 조건: 2,000원. 둘 다 편집할 수 있습니다.
- 조건 금액에 **정확히 일치**하는 후원만 해당 룰렛을 한 번 실행합니다. 큰 금액을 나누어 여러 번 돌리지 않습니다.
- 활성 룰렛의 조건 금액은 중복할 수 없습니다. 여러 룰렛을 추가해 금액별로 구분할 수 있습니다.
- 확률은 0.1% 단위, 합계는 정확히 100%. 0% 항목은 추첨되지 않습니다. 내부 확률은 0~1000의 정수입니다.
- 공격은 메소를 더하고 방어는 뺍니다. 방어 항목에도 양의 메소 크기를 입력하면 화면에서 음수로 표시됩니다.
- 애니메이션 시간 0.1~60초, 결과 표시 시간 0~30초. 대기열의 총 처리 시간은 둘의 합계입니다.
- 기본 메소 항목: 0 / 10만 / 50만 / 100만 / 300만 / 500만 / 1천만. 기본 확률: 30 / 25 / 20 / 15 / 6 / 3 / 1%.
- 새 설정은 다음 후원부터 적용됩니다. 진행 중이거나 대기 중인 후원은 수신 당시 항목·시간을 유지합니다.
- 음수를 끄면 잔액은 0에서 멈춥니다. 잔액 한도는 ±1조 메소이며 한도 적용 시 실제 증감을 따로 표시합니다.
- 시작 메소 설정은 저장만으로 현재 잔액을 바꾸지 않습니다. ‘저장된 시작 메소로 초기화’ 버튼을 사용하세요.
- 테스트 후원도 잔액에 반영되며 기록에 테스트로 표시됩니다. 잔액 변경·초기화는 대기열이 모두 끝난 후 가능합니다.

## OBS

관리자 대시보드 → **연결 & OBS**에서 주소를 복사해 OBS의 브라우저 소스에 붙여 넣습니다.

- 룰렛 오버레이: `/overlay.html?token=...`, 권장 800 × 800.
- 메소 잔액 오버레이: `/meso.html?token=...`, 권장 640 × 220.
- 배경은 투명합니다. 룰렛 당첨은 서버에서 확정되므로 OBS 창 개수와 무관하게 메소가 한 번만 반영됩니다.
- URL 키는 오버레이 읽기 전용이며 관리자 설정을 변경할 수 없습니다. 표시 중인 후원자 정보가 포함되므로 주소를 공개하지 마세요.
- 연결이 끊기면 자동 재연결합니다. 진행 중인 룰렛에 재접속하면 서버 시각을 기준으로 같은 결과에 맞춰 회전을 복구합니다.

## YouTube 계정 연결

서비스 제공자가 먼저 Google Cloud에서 YouTube Data API v3를 활성화하고 OAuth 웹 애플리케이션을 등록해야 합니다. 이후 방송자는 연결 화면의 **Google로 YouTube 연결** 버튼으로 인증합니다.

1. Google OAuth 동의 화면을 구성하고 테스트 모드라면 연결할 계정을 테스트 사용자에 추가합니다.
2. ‘연결 & OBS’에서 OAuth Client ID / Client Secret을 저장합니다. 인증 값은 로컬 `data/connections.json`에 보관하고 브라우저에 다시 반환하지 않습니다.
3. 화면에 표시된 리디렉션 URI를 Google 앱의 승인된 리디렉션 URI에 정확히 등록합니다. 기본값은 `http://127.0.0.1:3000/oauth/youtube/callback`입니다.
4. 관리자 페이지도 동일한 기본 주소로 접속하세요. 서비스 도메인 사용 시 서버의 `PUBLIC_BASE_URL=https://...`을 지정하고 그 URI를 등록합니다.
5. YouTube 방송 URL을 저장하고 계정 연결을 진행합니다. 읽기 전용 `youtube.readonly` 권한을 요청합니다.
6. 라이브 방송을 시작하고 연결 상태가 ‘연결됨’인지 확인합니다. 연결됨은 API 응답 성공을 뜻하며 실제 유료 후원 검증은 별도로 필요합니다.

대안으로 `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`, `YOUTUBE_REFRESH_TOKEN`을 서버 환경 변수에 설정할 수 있습니다. 또는 만료 전까지 사용할 `YOUTUBE_ACCESS_TOKEN`을 설정할 수 있습니다. 환경 변수는 UI 값보다 우선하며 UI에서 제거되지 않습니다. `YOUTUBE_LIVE_CHAT_ID`는 방송 URL보다 우선합니다. 방송 URL·채팅 ID가 없다면 인증한 계정의 활성 방송 하나를 조회합니다.

조회 주기는 API의 `pollingIntervalMillis`를 따릅니다. 페이지 커서·이벤트 ID는 재시작 후에도 유지합니다. Super Chat / Super Sticker의 **KRW 후원만** 처리합니다. 외화 후원은 환율 규칙이 정해지지 않아 제외 건수를 표시합니다. 멤버십·선물·일반 채팅은 금액 후원 이벤트로 취급하지 않습니다. API 쿼터·방송 종료·인증 만료 오류는 연결 상태에 표시됩니다. 첫 조회가 반환하는 기존 채팅의 유료 후원도 처리하므로 방송 시작 전에 연결하세요.

필요한 HTTPS 목적지는 `accounts.google.com`, `oauth2.googleapis.com`, `www.googleapis.com`입니다. 네트워크 제한 환경에서는 허용해야 합니다. 현재 클라우드에서 실제 Google 계정 인증이나 유료 후원 수신은 검증하지 않았습니다.

공식 API 참고: [Live chat messages](https://developers.google.com/youtube/v3/live/docs/liveChatMessages/list), [OAuth 웹 서버 흐름](https://developers.google.com/identity/protocols/oauth2/web-server).

## 후원 수신 브리지 계약

아래 경로는 **이 앱의 자체 계약**입니다. 플랫폼의 원본 후원 페이로드를 그대로 보내는 웹훅이 아닙니다. 신뢰할 수 있는 브리지가 플랫폼에서 이벤트를 받아 다음 형식으로 변환하고 서명해야 합니다. 브리지 구현은 별도 작업입니다.

`POST /webhooks/chzzk`, `/webhooks/soop`, `/webhooks/youtube`, `/webhooks/toonation`

```json
{
  "eventId": "platform-unique-donation-id",
  "nickname": "후원자",
  "amount": 10,
  "unit": "STAR"
}
```

`unit`은 `KRW` 또는 SOOP 전용 `STAR`, 금액은 양의 정수입니다. 예시는 SOOP 별풍선 10개 = 1,000원입니다. 다른 플랫폼에서는 원화 정수 금액을 보내세요. `eventId`는 재전송해도 동일해야 합니다. 중복 ID는 플랫폼별로 분리되어 영구 저장됩니다.

서명 헤더:

- `X-Webhook-Timestamp`: 현재 Unix 시간, **밀리초** 문자열. 서버와 5분 이상 차이나면 거절됩니다.
- `X-Webhook-Signature`: `HMAC-SHA256(WEBHOOK_SECRET, timestamp + "." + rawBody)`의 hex 문자열.
- `Content-Type: application/json`

`WEBHOOK_SECRET`은 서버 환경 변수 또는 `data/keys.json`의 `webhook` 값입니다. 서명은 정확히 전송할 원본 JSON 바이트를 기준으로 생성해야 합니다. 플랫폼이 기본 제공하는 서명 방식과 동일하다고 가정하지 마세요. 수신 응답의 `matched`가 false이면 금액 조건에 맞는 활성 룰렛이 없다는 뜻입니다. 400/500 응답은 해결 후 같은 eventId로 재시도하세요. 대기열은 최대 1,000건입니다.

## 저장 및 운영

`data/state.json`에 설정·잔액·대기열·당첨 결과·중복 방지 ID·YouTube 페이지 커서를 저장합니다. 임시 파일 쓰기 후 rename으로 파일을 교체합니다. 서버 재시작 시 진행 중인 당첨 결과를 유지하고 중복 반영하지 않습니다. 최근 후원·결과는 각 500건까지 보관하고 중복 방지 ID는 삭제하지 않습니다.

이 구현은 **단일 Node.js 프로세스**용입니다. 같은 `DATA_DIR`에 여러 서버를 실행하거나 여러 인스턴스로 확장하지 마세요. 큰 규모의 장기 운영에는 트랜잭션 DB와 중복 ID 보관 정책이 필요합니다. JSON 저장이므로 메모리·파일 크기·디스크 상태를 모니터링하고 data 디렉터리를 안전하게 백업하세요. 개인정보·유료 이벤트의 운영 보관 정책은 별도로 정해야 합니다.

외부 네트워크 접근이나 플랫폼 자격 증명 없이 룰렛 본체 테스트를 할 수 있습니다. 재사용 환경에서는 기존 `/workspace/apiSetting` 체크아웃을 사용하며 별도 Git worktree가 필요하지 않습니다. 스냅샷이 프로세스를 유지하지 않으므로 새 작업에서는 `npm start`로 서버를 다시 시작해야 합니다.

## 검증

```sh
npm run check
npm test
```

24개의 기존 구현 테스트가 확률 경계, 금액 일치, 별풍선 환산, 대기열, 중복 방지, 재시작 복구, 공격·방어 잔액, 관리자/오버레이 인증 분리, 웹훅 서명, SSE 이벤트, OAuth state 검증과 YouTube API 응답 처리를 검사합니다. YouTube API 응답은 모의 응답이며 외부 플랫폼의 실제 후원 수신 검증과 구분해야 합니다.

선택적 브라우저 검증: Python Playwright와 Chromium이 설치된 환경에서 `python3 scripts/browser-smoke.py`를 실행합니다. 기존 서버·실제 방송 잔액을 변경하지 않고 임시 데이터·별도 포트를 사용합니다. `CHROMIUM_PATH`로 브라우저 경로, `MESO_SCREENSHOTS_DIR`로 스크린샷 출력 폴더를 지정할 수 있습니다.

브라우저 검증은 별도의 임시 데이터로 관리자 로그인, 설정 합계 검증, 정확한 후원 조건, SOOP 환산, 공격·방어·음수 잔액, 잔액 초기화, OBS SSE 갱신, 모바일 화면을 확인했습니다. 실제 플랫폼 연동·OBS 데스크톱 프로그램 자체는 검증하지 않았습니다.

현재 클라우드 설정 초안에는 설치 스크립트, 서버 시작 절차, Google 인증·API 및 플랫폼 문서에 필요한 HTTPS 도메인을 저장했습니다. 초안 저장은 실행 중인 네트워크 변경이나 게시 완료를 의미하지 않습니다. 환경 설정에서 검토·저장한 뒤 게시해야 재사용 환경에 적용됩니다.
